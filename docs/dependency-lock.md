# OCaml dependency lock workflow

The checked-in `freight_capacity_auction_clearing_engine.opam` is the authoritative manual manifest. `dune-project` deliberately keeps `(generate_opam_files false)`. The adjacent `freight_capacity_auction_clearing_engine.opam.locked` is a full transitive lock generated by opam; it is not a hand-edited dependency list.

## Supported acceptance platform

The current lock has been generated and freshly consumed on **Linux x86_64** with opam 2.5.2 and `ocaml-base-compiler.5.2.0`. It keeps Alcotest 1.9.1 and OUnit2 2.2.7 conditional on `with-test` while pinning their transitive closure.

Native Windows is not yet an accepted lock-consumption platform. Deterministic PowerShell contract tests prove the verifier's fake-client argument, failure-code, safety, drift, mutation, and cleanup behavior only; they do not prove a Windows OCaml toolchain. No retained artifact proves a native Windows fresh switch or an actual-client PowerShell verifier pass. Do not interpret the Linux lock or PowerShell contract behavior as cross-platform proof. A future Windows acceptance run must execute opam 2.5.2, consume this lock in a clean native switch, run the actual PowerShell verifier, and pass the project gates. If the full lock is not portable, introduce an explicitly reviewed platform lock instead.

The lock pins opam package versions. It does **not** pin OS/depext packages, opam-repository snapshots, C toolchains, compiler flags, CPUs, or package binaries, and it does not promise byte-identical builds.

## Normal fresh install

Use an official opam client that supports the 2.2 CLI. From the repository root:

```sh
opam --version
opam --cli=2.2 switch create . 5.2.0 --deps-only --with-test --locked
bash scripts/verify-opam-lock.sh
opam --cli=2.2 exec --switch=. -- dune build @check
```

PowerShell uses the same switch command and the native verifier:

```powershell
opam --version
opam --cli=2.2 switch create . 5.2.0 --deps-only --with-test --locked
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/verify-opam-lock.ps1
opam --cli=2.2 exec --switch=. -- dune build @check
```

Do not omit `--with-test`: the lock intentionally retains `with-test` filters.

## Existing-switch reconciliation

For an existing exact project switch that was initially created with `--with-test`:

```sh
opam --cli=2.2 install . --switch=. --deps-only --locked
bash scripts/verify-opam-lock.sh
```

A full transitive opam lock makes every pinned package a direct constraint. In opam 2.5.2, combining `--deps-only --with-test --locked --check` then requests the test dependencies of every locked package, not only this project's conditional Alcotest/OUnit2 dependencies. The executable verifier therefore performs the semantically complete split: `--deps-only --locked --check`, exact installed Alcotest/OUnit2 checks, and source/lock `with-test` filter checks. Fresh creation still uses `--with-test` and is the evidence that those project test dependencies were consumed. Do not weaken the lock or install unrelated dependency test suites merely to force the unsafe combined check form to pass.

The verifier checks:

- `ocamlc -version` equals 5.2.0 through the selected switch;
- the switch invariant is `ocaml-base-compiler = 5.2.0`;
- source and lock lint;
- `opam install . --deps-only --locked --check`, paired with exact installed project-test-dependency checks rather than the over-broad combined `--with-test` form described above;
- installed Alcotest 1.9.1 and OUnit2 2.2.7;
- a temporary full `opam lock` is LF-normalized and byte-equal to the tracked lock;
- no local pin, `file://` URL, absolute host path, credential-shaped URL, opam cache, or `_opam` path occurs in the lock;
- temporary files are removed on success and failure.

Stable verifier exits are: 10 input, 20 opam invocation, 21 compiler, 22 switch invariant, 23 lint, 24 locked reconciliation, 25 test dependencies, 26 lock drift/generation, and 27 unsafe lock content.

## Deliberate lock update

Lock updates are reviewed changes, never part of a normal install:

```sh
opam --cli=2.2 update
opam --cli=2.2 switch remove . --yes
opam --cli=2.2 switch create . 5.2.0 --deps-only --with-test
opam --cli=2.2 lock ./freight_capacity_auction_clearing_engine.opam
bash tests/tooling/opam-lock-contract.sh
bash scripts/verify-opam-lock.sh
```

Run the PowerShell contract and verifier on Windows when claiming Windows support. Never use `--direct-only` or `--keep-local`; the tracked artifact must contain the transitive closure and no machine-local pins. Review the complete lock diff, then run the full project gates.

## Depext boundary

Host packages are outside this lock. Linux currently needs equivalents of GMP, OpenSSL, libev, PostgreSQL client development headers, and `pkg-config`; Windows uses its MinGW/Cygwin equivalents. Provision them per runner. `--assume-depexts` and `--no-depexts` skip checks rather than lock system packages and must not be used as reproducibility evidence.

## Future CI inputs

No Linux/Windows CI matrix is implemented or proven by this workflow. When CI is introduced, use `ocaml/setup-ocaml@v3` with quoted `ocaml-compiler: "5.2.0"`, `opam-pin: false`, and initially `dune-cache: false`. Run the locked test-inclusive install and the platform verifier. Do not add broad caches for `_opam`, an opam root/download cache, `_build`, credentials, or absolute workspace paths. `--locked` generally does not replace an already pinned local package, which is why `opam-pin: false` is required. Keep every platform claim scoped to the jobs that have actually consumed the lock and passed the actual verifier.
