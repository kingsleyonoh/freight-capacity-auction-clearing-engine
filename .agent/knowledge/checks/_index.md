# Project-Local Checks (catalog)

> **One file per check.** Each check is advisory project-local guidance maintained by ordinary AI/Mesh workflows from path-backed recurrence evidence. An implementation lane reviews matching checks before planning and revises a triggering approach; Runtime v2 never dispatches, validates, or accepts these checks.
>
> Checks are project-local by design. Stack-class candidates may be reviewed through `/harvest-gotchas` for possible promotion to template knowledge.
>
> Retire a check through evidence-backed review when its target pattern no longer exists in the codebase. Do not reconstruct retired fixed-role reinforcement counters or controller-owned state.
>
> Filename convention: `{failure_type}-{slug}.md` (lowercase, hyphenated). Example: `tests-wont-green-mock-database-in-integration.md`.
